# Document IDE 1.0.2

**Scope:** developer machine only. This release adds local auto-update and moves the
installer to a per-user location.

## What ships

- The five 1.0.1 hotfixes (`hotfix/v1.0.1`).
- **Per-user MSI** under `%LOCALAPPDATA%\Programs\Document IDE`; no administrator
  rights or UAC prompt.
- **Local auto-update** for the developer's own machine:
  `scripts/dev-autoupdate.ps1` polls `origin/master` every 60 s, builds a dedicated
  worktree (`D:\document-ide-master`), waits until the app is idle, saves dirty
  Markdown editors, swaps the install directory, restarts, health-checks the new
  build, and rolls back on failure.
- **Build identity**: `GET /api/app/status` reports the installed version and
  commit SHA; `build-info.json` travels with the payload.

## One-time migration from 1.0.0.0 (per-machine)

A per-machine 1.0.0.0 installation cannot be upgraded in place to a per-user
product (different Windows Installer installation context), so migrate once:

1. Close Document IDE.
2. **Settings → Apps → Installed apps** (or *Apps & features*) → **Document IDE
   1.0.0.0** → **Uninstall**. This step needs the administrator prompt.
3. Run the new `DocumentIDE-Setup.msi` (1.0.2.0). It installs per-user and does
   **not** prompt for elevation.
4. Launch **Document IDE** from the Start menu.

Documents, the database, history and the WebView profile under
`%LOCALAPPDATA%\DocumentIDE` are untouched by this migration.

## Enable automatic updates (developer machine only)

1. Merge the auto-update branch to `master` **first**. The running app must
   already include the `/api/app/*` control surface and the `runtime.json`
   handshake; otherwise a running app cannot be stopped safely.
2. From the repository:
   `pwsh -NoProfile -File scripts/install-dev-autoupdate.ps1`
3. The task **DocumentIDE Dev Auto-Update** runs at logon as the current user at
   the limited run level.
4. Log: `%LOCALAPPDATA%\DocumentIDE\logs\autoupdate.log`.
5. Disable: `pwsh -NoProfile -File scripts/install-dev-autoupdate.ps1 -Uninstall`.
6. Manual one-shot: `pwsh -NoProfile -File scripts/dev-autoupdate.ps1 -Once`.

## Behaviour and safety

- Only a new `origin/master` SHA triggers a build. The last successfully
  installed SHA is recorded in `%LOCALAPPDATA%\DocumentIDE\last-built.sha`.
- A restart is deferred while backend mutations are in flight (`busy`) and when a
  dirty editor cannot be saved (`prepare-restart` returns `ok: false`).
- If the app is not running, the payload is staged and swapped but the app is not
  launched.
- A failed build, failed swap or failing new build leaves the previous install
  working; the `install.old-<suffix>` directory is restored and the old app is
  relaunched. The failed SHA is recorded in
  `%LOCALAPPDATA%\DocumentIDE\bad-shas.txt` and is not retried until a new
  `master` commit or a manual `-Force` run.
- The watcher never touches documents, the database, history or the WebView
  profile. The control token from `runtime.json` is never logged.

## Not included

Public/end-user auto-update, delta patches, code signing, and CI-triggered
deployment.
