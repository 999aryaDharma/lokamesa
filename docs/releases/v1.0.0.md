## What ships

- **Local-first document IDE** for Windows: the filesystem is the source of truth; the app stores
  workspace metadata, an index and audit history, never authoritative document content.
- **Three-pane macOS-style shell** with a 12-screen design system: canvas (folder/file objects with
  click-to-open folders that fan out their **real** contained documents), list, graph with explicit vs
  inferred edges, search with preview, Markdown editor with live preview, share manager, and PDF.
- **Batch review workflow**: deterministic, recursive, previewable, reviewed-plan Search & Replace with
  apply and undo, recovery snapshots and a 30-day history (with a real operation listing).
- **DOCX**: document-aware Git diff, inspect/index, open in Microsoft Word (deep editing stays in Word),
  and a bounded preview-content API for the canvas.
- **Source control** (30 privileged routes): status, stage/unstage (single and all), commit/commit-all,
  explicit fetch, fast-forward-only pull, explicit push, commit and file history, file versions, conflict
  state and resolution shell, worktree discovery/create/remove/prune, safe discard/restore with
  recovery-or-block, and correlation with Document IDE History.
- **Public sharing** via a separate `ShareHost` process (no privileged mutation or Word dependencies),
  with token/CSP/rate-limit controls, and an owner share surface for create/stop/revoke.
- **Context pack** (copy-only) built from real `.md` sources and indexed `.docx` text, and
  missing-document detection with reference-only removal that never touches the file.

## Known limitations

These are documented in full in the readiness report; none blocks this release.

- **Quick Look** (Word → PDF → page image) is not implemented; the overlay is absent by design, not
  stubbed.
- Share viewer-side stop/revoke is not enforced **cross-process**; a viewer already holding a valid token
  may keep reading until it expires.
- Operation-history recording is **at-most-once**: if the database write fails after a successful
  mutation, the failure is surfaced (`409`) but the operation is absent from the listing (the per-file
  JSONL audit still exists).
- SCM service registration exists in two places (`Program.cs` and `AddSourceControlServices`); a recorded
  cleanup, no behaviour risk.
- Removing a document reference leaves an orphaned `search_content` row (the file is never touched).
- Known NuGet advisories on `HtmlSanitizer`, `AngleSharp` and `SQLitePCLRaw` are pending a dependency
  sprint.
- Context-pack output is copy-only because no file export destination is defined.
