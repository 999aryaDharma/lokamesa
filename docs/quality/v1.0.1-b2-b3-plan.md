# B2/B3 fix plan — ShareHost token authentication + cross-process stop/revoke

**Branch:** `hotfix/v1.0.1`
**Chosen posture:** fail-closed (a share package with no token hash is denied).

## Root cause

ShareHost is a separate process that only reads the share package on disk
(`%LOCALAPPDATA%\DocumentIDE\shares\<shareId>\`). It cannot read the owner DB
(architecture test forbids an Infrastructure reference). Today:

- `ShareTokenMiddleware` runs only when `X-Share-Token` is present and proceeds
  **without validation** when it is absent (`ShareTokenMiddleware.cs:41-46`).
- `ShareTokenService.GenerateTokenForShare` has no production caller, so the
  in-memory hash map is always empty.
- `ShareLifecycleService.StopAsync`/`RevokeAsync` only change DB columns; the
  on-disk package is never updated, so a stopped/revoked link keeps serving.

## Design

Carry the auth state in the share package as a sidecar `access.json`
(so the token hash is never served by `/share/{id}/manifest` or the artifact
route):

```json
{ "shareId": "...", "tokenHash": "<sha256 hex>", "expiresAt": null }
```

- `ShareAccessPolicy` (DocumentIDE.Core.Sharing) is the record.
- `ShareTokenService` gains `WriteAccessPolicy`, `ReadAccessPolicy`,
  `IsAccessGranted(shareId, token)` — **fail-closed**: missing policy,
  missing/empty hash, past expiry, or missing/mismatched token all deny.
- Publishers write the policy on publish; `ShareLifecycleService`
  stop/revoke/regenerate rewrite it (stop = past expiry, revoke = empty hash,
  regenerate = new hash + null expiry).
- `ShareTokenMiddleware` requires a valid token for every `/share/**` request
  (header `X-Share-Token` or `?token=`), unconditionally.
- Artifact route refuses to serve `access.json`.

## TDD order

1. Core RED: `ShareTokenServiceTests` — policy write/read + `IsAccessGranted`
   fail-closed cases.
2. Host RED: `ShareTokenTests` (integration) — ShareHost rejects missing/wrong
   token, accepts the valid one, rejects stopped/revoked, fails closed.
3. Owner RED: `ShareLifecycleHostTests` — stop/revoke/regenerate rewrite the
   on-disk policy.
4. GREEN implementation.
5. Update the existing share lanes to authenticate (fail-closed).
