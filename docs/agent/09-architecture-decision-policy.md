# ADR Policy

Create an ADR when a decision:
- changes a process boundary,
- introduces/replaces a core dependency,
- changes data persistence identity,
- changes security boundary,
- changes file mutation semantics,
- accepts a material residual risk.

ADR states:
`Proposed → Accepted → Superseded`

Each ADR contains:
- Context
- Decision
- Alternatives
- Consequences
- Security/file-safety impact
- Testing evidence
- Supersedes/Superseded by
