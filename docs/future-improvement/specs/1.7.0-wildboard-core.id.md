# 1.7.0 — Wildboard Core (Terjemahan Indonesia)

**Label:** `future-improvement`
**Status:** Specified (Spesifikasi)
**Hasil utama:** tipe workspace kedua — canvas tak terstruktur dan local-first untuk brainstorming, ide, dan tulisan acak

> **Catatan status.** `SPECIFIED`. Diatur oleh `docs/decisions/ADR-003-wildboard-workspace-kind-and-vault.md` (**Accepted**). Sprint implementasi ada di `docs/future-improvement/sprints/v1.7.0/` (`WB-01`…`WB-05`). Versi ini tetap di luar board V1 aktif sampai owner mempromosikannya.
>
> **Catatan terjemahan.** Terjemahan tidak resmi dari `1.7.0-wildboard-core.md`. Jika ada perbedaan, versi Inggris adalah acuan.

## 1. Tujuan

Canvas Document IDE sekarang bersifat document-centric: setiap objek adalah file yang dilacak, dan setiap file mewarisi semantik dokumen (Word, Git, batch mutation, ekspor PDF). Itu benar untuk dokumen otoritatif, dan salah untuk **otak kedua**, di mana pengguna ingin menuangkan ide, coretan pemikiran, dan teks lepas tanpa harus memutuskan "ini dokumen apa".

`1.7.0` memperkenalkan tipe workspace kedua — **Wildboard** — yang memakai ulang mesin interaksi canvas yang ada, tetapi punya model objek sendiri, vault penyimpanan sendiri, dan tidak memiliki subsistem khusus dokumen.

Referensi produk: Spatial (get-spatial.com). `1.7.0` mencakup inti produk itu: sticky note, sheet, stack, dan capture instan. Penulisan kaya (`1.8.0`) serta media/webclips (`1.9.0`) menyusul.

## 2. Cakupan

**Termasuk**

- `workspaces.kind` (`documents` | `wildboard`), migrasi, dan gating subsistem berdasarkan kind.
- Vault konten per workspace dengan penulisan file atomik, recovery snapshot, dan trash.
- Model penempatan `space_objects` dan pengelompokan datar `stack_members`.
- Aksi "Open vault folder" dan "Export vault" (zip) agar konten di app data tetap bisa ditemukan dan di-backup.
- Jenis objek `text`, `sheet`, `stack`.
- Permukaan canvas wildboard yang memakai ulang pan/zoom/select/drag/persist.
- Quick Capture (hotkey global) yang membuat objek `text`.

**Tidak termasuk (versi berikutnya)**

- editing blok/rich dan formatting ala Medium (`1.8.0`),
- label, layer view, pencarian wildboard (`1.8.0`),
- gambar, video, link, webclips, PDF viewer, importer (`1.9.0`),
- sync/backup cloud,
- aplikasi mobile,
- import X/Twitter.

## 3. Kind workspace & isolasi

```sql
ALTER TABLE workspaces ADD COLUMN kind TEXT NOT NULL DEFAULT 'documents';
```

- `documents` — perilaku tidak berubah; semua workspace lama terisi nilai ini.
- `wildboard` — permukaan khusus dokumen **ditolak backend dan tidak dimount shell**:
  - integrasi Microsoft Word / DOCX dan deteksi lock editing,
  - mesin batch dan UI batch,
  - ekspor PDF,
  - sharing,
  - folder source dan reconciliation,
  - panel dan aksi Source Control (Git).

Penegakan:

- **Backend.** Setiap route dokumen ber-scope workspace mengembalikan `409 { "errorCode": "WorkspaceKindNotSupported" }` untuk workspace `wildboard`. Route berbasis document-id tidak perlu guard karena objek wildboard tidak pernah menjadi baris `documents`.
- **Frontend.** `GET /api/workspaces/{id}` mengembalikan kind dan set capability; panel/tombol dengan capability `false` tidak dimount.

Menyembunyikan atau menonaktifkan tombol tanpa penolakan backend tidak cukup.

## 4. Tata letak vault

```text
<vault-root>/
  notes/
    <object-id>.md        # objek text dan sheet
  links/
    <object-id>.md        # disiapkan untuk 1.9.0
  assets/                 # disiapkan untuk 1.9.0
```

- Vault root adalah `%LOCALAPPDATA%\DocumentIDE\vaults\<workspaceId>\`, dibuat saat penulisan pertama.
- Memindahkan vault ke folder pengguna **ditunda** setelah `1.7.0`; versi ini menyediakan aksi "Open vault folder".
- Setiap file ditulis dengan disiplin yang sama: tulis ke file temp di direktori yang sama, validasi, lalu move (file baru) atau replace (file lama) ke target.
- File objek `text` berisi isi catatan sebagai Markdown biasa. `sheet` memakai representasi yang sama.
- Identitas objek adalah `id` aplikasi, bukan nama file. Mengganti judul tidak perlu mengganti nama file.

## 5. Model domain

```text
space_objects
- id                    UUID, primary key
- workspace_id          FK -> workspaces(id) ON DELETE CASCADE
- kind                  text | sheet | image | video | link | webclip | stack | label
- canvas_x, canvas_y    REAL
- width, height         REAL
- vault_relative_path   TEXT NULL   (NULL hanya untuk stack/label)
- mime_type             TEXT NULL
- title                 TEXT NULL
- availability_status   available | missing   (default available)
- created_at, updated_at

stack_members
- stack_id              FK -> space_objects(id) ON DELETE CASCADE
- object_id             FK -> space_objects(id) ON DELETE CASCADE
- PRIMARY KEY (stack_id, object_id)
- UNIQUE INDEX pada (object_id)   -- objek paling banyak satu stack
```

`kind` memuat jenis masa depan (`image`, `video`, `link`, `webclip`, `label`) di skema untuk kompatibilitas maju, tetapi `1.7.0` **menolak membuatnya** — hanya `text`, `sheet`, `stack` yang bisa dibuat, dan penolakan itu diuji (`Unsupported_Kind_For_17_Is_Rejected`).

Invariant:

- `vault_relative_path` adalah path relatif ternormalisasi di dalam vault; path absolut dan segmen `..` ditolak.
- Objek milik tepat satu workspace.
- `stack` tidak punya file pendukung.
- Menghapus stack hanya menghapus pengelompokan; objek anggota tetap ada.
- Menghapus objek ber-file memerlukan konfirmasi eksplisit, dan file dipindahkan ke trash vault (bukan `unlink` langsung) sehingga masih bisa dipulihkan.
- **Setiap replace mengambil recovery snapshot konten sebelumnya. Jika snapshot gagal dibuat, penulisan diblokir** (non-negotiable yang sama dengan mesin mutasi dokumen; konten vault adalah sumber pengguna, bukan data turunan).
- Objek menjadi anggota paling banyak satu stack; stack tidak boleh menjadi anggota stack; anggota harus berada di workspace yang sama dengan stack.

## 6. Jenis objek di 1.7.0

### 6.1 `text` (sticky)

- Dirender sebagai kartu yang dapat di-resize di canvas.
- Isi disimpan di `notes/<id>.md`.
- Editing inline untuk teks pendek; teks panjang dapat membuka editor lebih besar.
- Judul default = baris pertama yang tidak kosong, dipotong untuk tampilan; judul tersimpan hanyalah metadata.

### 6.2 `sheet`

- Dirender sebagai kartu kertas yang lebih besar.
- Memakai penyimpanan `.md` yang sama.
- Membuka permukaan editing Markdown (`MD-01` sampai `1.8.0` menggantinya dengan block editor).
- Sheet adalah file nyata; nanti dapat dipromosikan menjadi dokumen terlacak.

### 6.3 `stack`

- Pengelompokan datar (tanpa nesting).
- Saat collapsed tampil sebagai tumpukan ringkas berisi jumlah; saat expanded menampilkan anggota.
- Drag masuk dan keluar stack.
- Posisi stack independen dari posisi anggota; expand mengembalikan tata letak relatif anggota dari koordinat tersimpan.

## 7. Permukaan canvas

Pemakaian ulang komponen yang ada bersifat wajib, bukan opsional:

| Concern | Dipakai ulang dari |
|---|---|
| pan/zoom/transform viewport | `features/canvas/DocumentCanvas.tsx` |
| seleksi (klik, additive, rect) | `features/canvas/selection/SelectionController.ts` |
| group drag | `SelectionController.groupDrag` |
| persistensi posisi | pola dari `usePersistedPosition.ts` |
| kontrak store | `useSyncExternalStore` + snapshot ter-cache |
| indeks spasial / tidy | `layout/SpatialIndex.ts`, `layout/TidyLayout.ts` |

Perbedaan:

- sumber objek adalah `space_objects`, bukan `workspace_documents`;
- renderer spesifik per kind (`text`, `sheet`, `stack`);
- double-click membuka editor wildboard, tidak pernah Microsoft Word;
- empty state menawarkan "capture a thought" dan "create sheet".

## 8. Quick Capture

- Shortcut global membuka panel minimal satu kolom.
- Submit membuat objek `text` di wildboard aktif (atau wildboard default yang dikonfigurasi) dan menempatkannya di posisi yang tidak bertumpuk.
- `Escape` menutup tanpa menulis.
- Panel tidak melakukan I/O jaringan.
- Kepemilikan hotkey: desktop host (`FND-07`) mendaftarkannya; shell menyediakan binding in-app sebagai fallback.

## 9. Keamanan file

- Semua path vault dikanonikalisasi di bawah vault root; traversal dan escape reparse-point ditolak dengan error bertipe.
- **Setiap replace mengambil recovery snapshot konten sebelumnya sebelum penulisan temp; jika snapshot tidak bisa dibuat, penulisan diblokir.**
- Penulisan atomik (temp → validasi → rename); penulisan gagal tidak merusak konten sebelumnya.
- Penghapusan bukan `unlink`: file dipindahkan ke `<vault>/.trash/` dan bisa dipulihkan sampai pengguna mem-purge-nya. Menghapus penempatan saja tidak pernah menyentuh file.
- Tidak ada command line yang dibangun dari judul, path, atau metadata objek.
- Objek wildboard dikecualikan dari privileged local API dan permukaan ShareHost.
- Tidak ada mesin mutasi dokumen yang dapat dijangkau dari workspace wildboard.

## 10. Persistensi & siklus hidup

- Penempatan dan metadata di SQLite.
- Konten di vault sebagai file biasa.
- Crash recovery: saat startup, file temp yatim dihapus, dan objek yang file pendukungnya hilang ditandai `missing` (penempatan dipertahankan, tidak pernah dihapus diam-diam).
- File yang dihapus berada di `<vault>/.trash/`; trash bisa dilihat, dipulihkan, dan di-purge lewat aksi pengguna eksplisit.
- Objek ber-file hilang dapat dibuat ulang kosong, di-relink, atau dihapus lewat aksi pengguna eksplisit.

## 11. Pencarian & indexing

Tidak ada di `1.7.0`. File wildboard tidak dimasukkan ke `documents`, jadi tidak diindeks pipeline FTS5 yang ada. Pencarian datang di `1.8.0` dengan indeks khusus wildboard atau jalur promosi eksplisit.

## 14. Kriteria penerimaan

- [ ] Workspace lama terbuka tanpa perubahan setelah migrasi; `kind = 'documents'`.
- [ ] Workspace wildboard tidak mengekspos Word, batch, ekspor PDF, atau Git.
- [ ] Membuat sticky atau sheet menulis file `.md` nyata di vault.
- [ ] Editing sticky tersimpan ke file tersebut; membuka ulang memulihkan isi.
- [ ] Penulisan gagal tidak merusak isi file sebelumnya.
- [ ] Replace yang recovery snapshot-nya gagal dibuat **diblokir**, dan file lama tidak berubah.
- [ ] Menghapus objek ber-file memindahkan file ke trash vault; bisa dipulihkan, dan purge bersifat eksplisit.
- [ ] "Export vault" menghasilkan zip berisi semua file objek; "Open vault folder" membuka root vault.
- [ ] Hanya `text`, `sheet`, `stack` yang bisa dibuat di `1.7.0`; jenis masa depan ditolak (diuji).
- [ ] Satu objek tidak bisa menjadi anggota dua stack (unique index, dibuktikan test).
- [ ] Stack mengelompokkan dan melepas tanpa menyentuh file anggota.
- [ ] Quick Capture membuat objek `text` tanpa I/O jaringan.
- [ ] Upaya path traversal dan escape reparse-point ditolak.
- [ ] Canvas tetap responsif pada 1.000 objek.
- [ ] Tidak ada konten wildboard yang muncul di ShareHost atau privileged API.

## 15. Non-goals

- sync cloud atau backend sinkronisasi,
- multiplayer real-time,
- pembuatan atau editing DOCX dari wildboard,
- format konten proprietary,
- pembuatan folder fisik dari stack,
- promosi otomatis file wildboard menjadi dokumen terlacak.

## 16. Risiko & pertanyaan terbuka

1. **Dua store objek.** Pencarian, sharing, dan ekspor harus dijembatani eksplisit, bukan menumbuhkan coupling tak sengaja.
2. **Kebocoran UI.** Gating harus diverifikasi lewat tes, bukan inspeksi visual.
3. **Discoverability vault.** Penyimpanan terkelola butuh aksi "buka vault" dan cerita backup yang terdokumentasi.
4. **Pertumbuhan ukuran.** Media (1.9.0) butuh kuota; rancang interface-nya sekarang.
5. **Terjawab:** vault berada di app data untuk `1.7.0`; relokasi ditunda.
6. **Terjawab:** sheet hanya untuk wildboard di `1.7.0`; workspace `documents` tidak berubah.
7. **Terjawab:** shortcut Quick Capture in-app adalah `Ctrl+Shift+Space` (`Alt+Space` milik menu sistem Windows).
8. **Ditunda:** relink objek `missing` ke file vault lain yang sudah ada; `1.7.0` hanya menawarkan "recreate empty" dan "remove".
