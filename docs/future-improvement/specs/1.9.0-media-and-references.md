# 1.9.0 — Media & References

**Label:** `future-improvement`
**Status:** Candidate
**Primary outcome:** the wildboard accepts the material a second brain actually collects — images, video, links, page snapshots, PDFs — without becoming a cloud service or a security hole

> **Status note.** `CANDIDATE` proposal, governed by `ADR-003` (Accepted). Sprint decomposition is tentative until promotion.

## 1. Purpose

A second brain is mostly visual and referential: screenshots, mood-board images, clips, links, PDFs, and web pages worth keeping. `1.7.0` stored text; `1.8.0` made writing good; `1.9.0` makes the board able to hold everything else — while keeping every asset on the local filesystem.

Spatial's webclips capture a "magazine-style" snapshot of a URL in full desktop layout. That is the most valuable and most dangerous capability in this version: it requires outbound network access, rendering untrusted content, and storing the result. It therefore ships last and behind the strictest controls.

## 2. Scope

**In scope**

- Media storage and import pipeline (validation, quotas, thumbnails).
- `image` object kind.
- `video` object kind.
- `link` object kind.
- `webclip` object kind (bounded, explicit, sanitized).
- PDF import and in-app viewer.
- Import of `.md`, `.txt`, `.rtf`, and copied text.
- Explicit promotion of a wildboard file into a tracked document.

**Out of scope**

- streaming media from remote URLs (assets are local copies),
- automatic background crawling or link previews,
- cloud media hosting,
- SVG (not supported by the reference product; optional), DOC/DOCX/ODT import,
- X/Twitter bookmark import.

## 3. Media storage

```text
<vault>/assets/<sha256-prefix>.<ext>
```

Rules:

- Content type is determined by **byte sniffing**, not by the supplied extension or filename.
- Unsupported or mismatched content is rejected with a typed error; nothing is written.
- Per-file and per-workspace quotas are enforced and surfaced to the user.
- Duplicate imports are deduplicated by content hash.
- Originals are never modified. Thumbnails are derived and may be regenerated.
- Deleting the last object referencing an asset requires explicit confirmation and removes the asset.

## 4. Object kinds

### 4.1 `image`

- Formats: `png`, `jpeg`, `gif`, `webp`, `tiff`, `bmp`, `heic`, `avif`, and common raw formats where a decoder is available.
- Rendered as a resizable canvas object with a cached thumbnail.
- Animated formats (`gif`, `webp`) may animate on the canvas or render a static poster; the choice is explicit and bounded.
- Full-resolution viewing opens a lightbox; no editing.

### 4.2 `video`

- Formats: `mp4`, `mov`, `webm`, `avi`, `gif`/`webp` as short clips.
- Rendered as a poster frame on the canvas; playback is explicit (click to play) and never autoplays.
- Poster frames and duration are extracted at import.
- Large files are copied, not linked, so the board does not break when the source moves.

### 4.3 `link`

- Stored as `links/<id>.md` with YAML frontmatter:

  ```yaml
  ---
  url: https://example.com
  title: Example
  captured_at: 2026-10-18T00:00:00Z
  ---
  ```

- Rendered as a compact card.
- **No automatic network fetch** in this version for plain links: title and URL are user-supplied or taken from the paste.
- Because the payload is Markdown, a link object is inspectable and portable.

### 4.4 `webclip`

- Explicit user action only. The user pastes a URL and confirms capture.
- The page is fetched and rendered by an isolated capture step; the result is stored as a local image or PDF plus metadata.
- Requirements:
  - schemes limited to `https` and `http`,
  - private, loopback, link-local, and metadata address ranges are refused (SSRF protection),
  - redirects followed only within the same policy,
  - response size, time, and render-time limits enforced,
  - no cookies, credentials, or authenticated sessions are used,
  - rendered content is treated as untrusted and sanitized before display,
  - the captured artifact is advertised as a point-in-time snapshot, not a live page.
- Failure is typed and never partially writes an artifact.

### 4.5 PDF

- Import copies the PDF into the vault; the viewer renders pages locally.
- The repo already exports PDF (`PDF-01`…`PDF-04`); this version adds **import and view**.
- No PDF editing.
- Password-protected or malformed PDFs surface a typed failure.

## 5. Importers

| Input | Behaviour |
|---|---|
| `.md` | copied into `notes/`; frontmatter preserved |
| `.txt` | wrapped as Markdown without altering content |
| `.rtf` | converted to Markdown; unsupported constructs preserved as text |
| copied text | creates a `text` object |
| copied image | creates an `image` object from clipboard bytes |

No importer may execute content or follow embedded links.

## 6. Promotion to a tracked document

- An explicit action moves or references a wildboard file into a `documents` workspace.
- Promotion requires the target folder source and the normal filesystem safety path.
- After promotion the file becomes a `Document` and gains indexing, Git, and batch semantics.
- Promotion is never automatic; demotion is not supported.

## 9. Acceptance criteria

- [ ] A file with a spoofed extension is rejected by content sniffing.
- [ ] Quota exhaustion produces a typed error and writes nothing.
- [ ] Images and videos render from local copies; moving the original does not break the board.
- [ ] Video never autoplays.
- [ ] Link objects are plain Markdown with frontmatter.
- [ ] Webclip refuses loopback/private ranges and applies size and time limits.
- [ ] Captured web content is sanitized before display.
- [ ] PDF import renders locally without network access.
- [ ] Promotion goes through the existing filesystem safety path and produces a tracked `Document`.
- [ ] No importer executes content.

## 10. Non-goals

- hosted media or CDN,
- link unfurling in the background,
- OCR or document understanding,
- media editing (crop, trim),
- proprietary asset formats.

## 11. Risks & open questions

1. **SSRF and untrusted rendering** are the highest-risk items in the whole roadmap. `MR-05` must not ship without **a dedicated security ADR** (scheme allow-list, redirect policy, loopback/private/metadata refusal, DNS-rebinding, size/time limits, sanitization, storage and render isolation) accepted before implementation, plus dedicated security tests and review.
2. **Storage growth** — video especially. Quotas and clean-up must be designed in `MR-01`, not bolted on.
3. **Decoder availability** — HEIC/raw support depends on the platform; unsupported formats must degrade explicitly.
4. **Preview HTML** — rendering arbitrary HTML in the Electron shell is unacceptable; capture must use an isolated renderer.
5. **Open question:** whether webclips store a full-page PDF, an image, or both.
