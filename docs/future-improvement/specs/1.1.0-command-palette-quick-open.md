# 1.1.0 — Command Palette & Quick Open

**Label:** `future-improvement`
**Status:** Specified
**Primary outcome:** keyboard-first control and fast document navigation

## 1. Purpose

Provide a universal command surface and a fast document/folder/workspace opener so experienced users can operate the Document IDE without hunting through menus.

## 2. Product boundary

### Command Palette

The palette discovers commands already supported by the application:

- open workspace/source,
- search documents,
- switch view,
- stage/unstage, commit, fetch, pull, push where SCM is available,
- open in Word, VS Code, Explorer, Terminal,
- run approved batch operations,
- create/export context pack,
- export PDF,
- open history, review, or health views.

The palette MUST NOT invent new operations that do not exist as application commands.

### Quick Open

Quick Open is optimized for:

- documents,
- folders,
- workspaces,
- recently opened items,
- currently indexed items.

## 3. Command registry

Each command has: 

```text
CommandId
DisplayName
Category
Keybinding
AvailabilityPredicate
Execute
DangerLevel
```

`DangerLevel` is at least:

```text
none
confirm
critical
```

Commands that mutate or discard files must preserve existing confirmation and safety gates.

## 4. Search behavior

Command Palette uses exact and fuzzy matching for command labels. Quick Open uses the existing local search/indexing infrastructure plus recent-item signals. Ranking must not change authoritative search semantics.

Suggested Quick Open ranking signals:

```text
exact filename match
path match
recently opened
recently modified
workspace relevance
```

No network service is required.

## 5. Keyboard interaction

Target defaults:

```text
Ctrl+Shift+P  Command Palette
Ctrl+P        Quick Open
Esc           Close
Enter         Execute/Open
Arrow keys    Navigate
```

Keybindings must be user-remappable in a later patch release only if a conflict-free implementation exists. Hard-coded defaults are sufficient for 1.1.0.

## 6. Safety

Before executing a destructive command, the palette must surface the same confirmation flow as the normal UI. Keyboard access must not bypass scope, stale-file, lock, recovery, or conflict checks.

## 7. Non-goals

- full shell terminal inside the palette,
- arbitrary command execution,
- branch-management UI,
- autonomous macros,
- global cloud command registry.

## 8. Acceptance baseline

- user can reach major supported actions without leaving the keyboard,
- Quick Open opens a document reliably across a large workspace,
- unavailable commands are not executable,
- destructive commands retain safety gates,
- no authoritative document contents are copied into a command index.
