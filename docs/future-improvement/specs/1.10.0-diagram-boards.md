# 1.10.0 — Diagram Boards (Native)

**Label:** `future-improvement`
**Status:** Specified — arah **native** dikunci (2026-10-18)
**Primary outcome:** whiteboard/diagram di dalam **Loka**, dibangun native di atas canvas yang sudah ada

> **Keputusan.** Opsi embed (Excalidraw/draw.io) dan hybrid **ditolak**. Lokamesa membangun engine diagram sendiri. Alasan dan pembandingnya ada di `ADR-004`.

## 1. Masalah

Loka bisa menampung teks, sheet, dan stack, tetapi belum bisa menampung **diagram**: kotak, panah, alur, sketsa, dan papan bebas.

## 2. Tingkat kemampuan

| Tier | Isi | Status |
|---|---|---|
| **T0 — Shape board** | kotak/ellipse/diamond/sticky, pindah, resize, rotate, warna, z-order, group, export SVG/PNG | target `1.10.0` |
| **T1 — Diagram** | teks di bentuk, konektor + binding, snapping, template | target `1.10.0` |
| **T2 — Sketch** | freehand ink, pressure, penghapus, routing lanjutan | target `1.10.0` |
| **T3 — Kolaborasi** | multi-user real-time | **tidak dikerjakan** |

## 3. Keputusan arsitektur

Engine diagram native, memakai:

- canvas engine yang sudah ada (pan/zoom/transform, selection, group drag),
- `space_objects` + vault (ADR-003) untuk penyimpanan,
- format `board JSON` terbuka dan berversi,
- tidak ada dependensi engine pihak ketiga.

## 4. Alternatif yang ditolak

| Opsi | Alasan ditolak |
|---|---|
| **Embed Excalidraw** | gaya visual berbeda, model data asing, bundle 46,8 MB unpacked, undo terpisah, dan terasa seperti aplikasi di dalam aplikasi |
| **Embed draw.io** | berat (mxGraph), stencil berlisensi tambahan, tidak nyambung dengan model objek kita |
| **Hybrid** | dua engine, dua model data, dua undo — biaya perawatan seumur produk |
| **tldraw** | lisensi non-OSI; produksi butuh lisensi berbayar |

Keputusan lengkap: `docs/decisions/ADR-004-native-diagram-engine.md`.

## 5. Pelajaran dari implementasi Excalidraw

Dipelajari dari source MIT `excalidraw/excalidraw` (master, 2026-10-18). Yang diambil adalah **pola**, bukan kode.

### 5.1 Model elemen

Satu bentuk dasar, bukan hirarki kelas:

```ts
type BoardElementBase = Readonly<{
  id: string;
  x: number; y: number;
  width: number; height: number;
  angle: number;

  strokeColor: string; backgroundColor: string;
  fillStyle: 'solid' | 'hachure' | 'cross-hatch' | 'zigzag';
  strokeWidth: number; strokeStyle: 'solid' | 'dashed' | 'dotted';
  roundness: null | { type: number; value?: number };
  roughness: number; opacity: number;
  seed: number;              // benih deterministik untuk shape "rough"

  index: string;             // fractional index untuk urutan
  groupIds: readonly string[]; // terdalam → terluar
  frameId: string | null;

  boundElements: readonly { id: string; type: 'arrow' | 'text' }[] | null;
  startBinding: FixedPointBinding | null;
  endBinding: FixedPointBinding | null;
  containerId: string | null;

  version: number;
  versionNonce: number;
  created: number | null;
  updated: number;

  isDeleted: boolean;
  locked: boolean;
  link: string | null;
  customData?: Record<string, unknown>;
}>;
```

Pelajaran penting:

- **`isDeleted`, bukan hapus fisik.** Undo delete dan rekonsiliasi menjadi mudah.
- **`index` (fractional index)** untuk urutan. Menyisipkan elemen tidak perlu menomori ulang semua elemen.
- **`seed`** membuat bentuk "tangan" deterministik antar-render.
- **`version` + `versionNonce` + `updated`** untuk rekonsiliasi. Kita tidak butuh `versionNonce` karena tidak ada kolaborasi (lihat §7).
- **`created` terpisah dari `updated`** dan tidak ikut berubah saat edit.

### 5.2 Binding dua arah

```ts
type FixedPointBinding = {
  elementId: string;
  fixedPoint: [number, number]; // 0..1 relatif terhadap width/height
  mode: 'inside' | 'orbit' | 'skip';
};
```

- Panah menyimpan `startBinding`/`endBinding`.
- Bentuk menyimpan `boundElements` (daftar panah/teks yang menempel).
- Binding memakai **rasio titik tetap**, bukan koordinat absolut — sehingga tetap menempel saat bentuk di-resize.
- Teks di dalam bentuk memakai `containerId` pada teks, dan bentuk menyimpan `boundElements`.

### 5.3 Mutasi & versi

`mutateElement`:

- melewati update yang tidak mengubah nilai (no-op),
- menaikkan `version`, mengacak `versionNonce`, memperbarui `updated`,
- menghapus cache bentuk bila `width`/`height`/`points`/`image` berubah.

`ElementUpdate` **mengecualikan** `id`, `updated`, dan `created`.

### 5.4 Undo/redo berbasis delta

```ts
class History {
  undoStack: HistoryDelta[];
  redoStack: HistoryDelta[];
  record(delta) {            // menyimpan delta TERBALIK
    if (delta.isEmpty()) return;
    undoStack.push(inverse(delta));
    if (!delta.elements.isEmpty()) redoStack.length = 0;
  }
}
```

Pelajaran penting:

- **Delta, bukan snapshot penuh.** Hemat memori dan cepat.
- **Delta terbalik** disimpan, sehingga undo cukup menerapkan entri.
- **Redo hanya dibersihkan oleh perubahan elemen**, bukan oleh perubahan UI (mis. klik untuk membatalkan seleksi).
- Saat menerapkan undo, `version`/`versionNonce` **dikecualikan** — undo dianggap aksi baru.
- Undo melewati entri yang tidak menghasilkan perubahan terlihat.
- Event `historyChanged(isUndoStackEmpty, isRedoStackEmpty)` untuk UI.

### 5.5 State terpisah

- `elements` = isi dokumen (serializable, tanpa state lokal).
- `appState` = state UI (seleksi, tool, scroll, tema).
- `files` = aset biner (gambar) di luar elemen.

Aturan: **elemen tidak boleh menyimpan state lokal peer**. Ini yang membuat serialisasi dan undo bersih.

## 6. Model data Lokamesa

Mengadopsi pola di atas dengan penyesuaian:

```ts
type BoardElementBase = {
  id: string;
  type: 'rect' | 'ellipse' | 'diamond' | 'sticky' | 'text'
      | 'arrow' | 'line' | 'freedraw' | 'image' | 'frame';
  x: number; y: number; width: number; height: number; angle: number;

  strokeColor: string; backgroundColor: string;
  fillStyle: 'solid' | 'hachure';
  strokeWidth: number; strokeStyle: 'solid' | 'dashed' | 'dotted';
  roundness: number | null;
  opacity: number;
  seed: number;

  index: string;
  groupIds: string[];
  frameId: string | null;

  boundElements: { id: string; type: 'arrow' | 'text' }[] | null;
  startBinding: FixedPointBinding | null;
  endBinding: FixedPointBinding | null;
  containerId: string | null;

  version: number;
  created: number;
  updated: number;

  isDeleted: boolean;
  locked: boolean;

  /** Lokamesa: tautan ke dokumen/objek Loka (bukan URL). */
  linkedDocumentId: string | null;
  linkedSpaceObjectId: string | null;

  customData?: Record<string, unknown>;
};
```

Envelope file:

```json
{
  "schema": "lokamesa.board.v1",
  "id": "<board-object-id>",
  "viewport": { "x": 0, "y": 0, "zoom": 1 },
  "elements": [],
  "appState": {},
  "files": {}
}
```

Lokasi: `vault/boards/<id>.json`.

## 7. Peningkatan dibanding Excalidraw

Perbedaan yang disengaja, selaras dengan aturan produk:

| # | Peningkatan | Alasan |
|---|---|---|
| 1 | **Undo terpadu** dengan undo aplikasi (satu batas operasi) | Excalidraw memisahkan undo board; kita bisa menyatukannya |
| 2 | **JSON ramah Git**: kunci terurut, `versionNonce` tidak disimpan | diff bersih; `versionNonce` tidak berguna tanpa kolaborasi |
| 3 | **Tautan ke dokumen** (`linkedDocumentId`) | board ikut graph/backlink — hal yang tidak dimiliki Excalidraw |
| 4 | **Aksesibilitas**: panel layer/daftar elemen | alternatif non-canvas untuk pengguna keyboard |
| 5 | **Offline total** (tanpa CDN/font eksternal) | aturan produk |
| 6 | **Tanpa telemetri/AI** | aturan produk |
| 7 | **Budget performa 5.000 elemen** | target eksplisit |
| 8 | **Export SVG/PNG deterministik** | hasil sama untuk isi sama |

Butir 1–8 diterapkan. Owner juga mengonfirmasi tiga tambahan untuk `1.10.0`:

- **Freehand ink (T2)** masuk versi pertama, bukan fase berikutnya.
- **Export PDF** selain SVG/PNG.
- **Template siap pakai**: flowchart, mind map, dan kerangka diagram.

**Snapping agresif tidak dipilih.** Snapping tetap ada sebatas kebutuhan konektor dan tepi objek; tidak ada snap-ke-grid yang memaksa secara default.

## 8. Cakupan `1.10.0`

**Termasuk**

- T0, T1, dan T2 penuh: bentuk, teks di bentuk, konektor + binding, group, frame, dan freehand ink.
- Undo/redo terpadu dengan undo aplikasi.
- Tautan elemen ke dokumen atau objek Loka.
- Panel layer sebagai alternatif keyboard.
- Export SVG, PNG, dan PDF.
- Template siap pakai: flowchart, mind map, kerangka diagram.
- Snapping dasar (tepi objek dan konektor); bukan snapping agresif default.

**Tidak termasuk**

- kolaborasi real-time (T3),
- paritas draw.io (UML/BPMN/Visio/stencil),
- import `.excalidraw`/`.drawio`,
- AI generate diagram,
- komponen pihak ketiga.

## 9. Sprint (tentatif)

| Sprint | Isi |
|---|---|
| `DB-01` | Kind `board`, envelope JSON, repository, API, vault `boards/` |
| `DB-02` | Model elemen + mutate/version + fractional index + store |
| `DB-03` | Render bentuk + resize/rotate/z-order/group/frame + selection |
| `DB-04` | Teks di bentuk + konektor + binding dua arah + snapping dasar |
| `DB-05` | Freehand ink + undo/redo terpadu |
| `DB-06` | Panel layer + aksesibilitas + tautan dokumen/backlink |
| `DB-07` | Template + export SVG/PNG/PDF + hardening performa |

Belum didaftarkan ke manifest/index sampai owner mengonfirmasi cakupan.

## 10. Kriteria penerimaan

- [ ] Board tersimpan sebagai JSON terbuka; bisa dibuka tanpa Lokamesa.
- [ ] Bentuk bisa dibuat, dipindah, di-resize, dirotasi, diberi warna, dan dikelompokkan.
- [ ] Panah tetap menempel saat bentuk digeser/di-resize.
- [ ] Teks di dalam bentuk mengikuti ukuran bentuk.
- [ ] Freehand ink bisa digambar, dihapus, dan ikut tersimpan.
- [ ] Undo/redo mencakup semua aksi dan terhubung ke undo aplikasi.
- [ ] Elemen bisa menautkan dokumen/objek Loka dan muncul di backlink.
- [ ] Panel layer memberi alternatif keyboard.
- [ ] Template flowchart, mind map, dan kerangka diagram bisa dipakai.
- [ ] Export SVG, PNG, dan PDF deterministik dan tersanitasi.
- [ ] 5.000 elemen tetap responsif sesuai budget.
- [ ] Tidak ada permintaan jaringan saat membuka board.

## 11. Non-goals

- kolaborasi real-time,
- format proprietary,
- ketergantungan pada engine pihak ketiga,
- mengganti canvas dokumen.

## 12. Pertanyaan terbuka

1. Apakah board boleh berisi objek `text`/`sheet` Loka, atau hanya elemen board?
2. Apakah frame dipakai sebagai "halaman" atau sekadar pengelompokan visual?
3. Apakah tautan dokumen ditampilkan sebagai badge di bentuk?
4. Berapa jumlah template awal yang masuk `1.10.0`?
