# 1.6.0 — Document Comments / Review Notes

**Label:** `future-improvement`
**Status:** Specified
**Primary outcome:** canvas-native note objects placed near documents for review, reminders, and work context

## 1. Purpose

Add a lightweight note object that lives beside a document on the canvas. The note is an application/workspace object, not content embedded into the underlying DOCX/Markdown file.

## 2. Core UX

Example:

```text
┌─────────────────────┐     ┌──────────────────┐
│ contract.docx       │     │ NOTE             │
│                     │ ─── │ Update amount    │
│                     │     │ before commit.   │
└─────────────────────┘     └──────────────────┘
```

The user can:

- create a note near a selected document,
- move the note on canvas,
- edit text,
- resolve/archive the note,
- reopen it,
- open the associated document.

## 3. Anchoring model

Notes support:

```text
free
document-anchored
```

A document-anchored note stores an offset relative to the document canvas object.

```text
Note
- id
- workspace_id
- document_id nullable
- anchor_mode
- anchor_offset_x nullable
- anchor_offset_y nullable
- canvas_x
- canvas_y
- text
- status
- created_at
- updated_at
```

When the document object moves, an anchored note follows it. The note does not alter physical file location.

## 4. Status

```text
open
resolved
archived
```

Resolved notes remain queryable/history-visible until archived or deleted according to normal workspace rules.

## 5. Canvas semantics

Notes participate in canvas layout but are not documents. They must not be interpreted as files, folders, or Git objects.

Tidy/reflow operations:

- may move free notes,
- may move anchored note offsets locally,
- must not move documents out of pinned positions merely to accommodate notes,
- must preserve note-document association.

## 6. Review integration

A Review Session may reference notes created during review. Approval of a review item does not automatically resolve its notes.

A future patch may support “Create note from finding” and “Resolve note when review item is approved,” but 1.6.0 should keep those actions explicit.

## 7. Search & indexing

Note text should be searchable in the application workspace index. Search results must label notes distinctly from documents.

Suggested query extensions:

```text
note:"payment"
status:open
linked:agreement.docx
```

The query grammar should extend the existing structured query mechanism rather than create a second parser.

## 8. Persistence

Notes are persisted in SQLite/workspace metadata. They may optionally be exportable in future formats, but V1.6.0 does not embed them into DOCX/Markdown.

## 9. Non-goals

- Word comments import/export,
- Microsoft Word tracked changes,
- multiplayer comment threads,
- email notification system,
- cloud comment storage.
