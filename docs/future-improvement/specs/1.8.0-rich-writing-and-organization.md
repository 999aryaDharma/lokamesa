# 1.8.0 — Rich Writing & Organization

**Label:** `future-improvement`
**Status:** Candidate
**Primary outcome:** a Medium-style writing surface that stores plain Markdown, plus the organizational affordances a second brain needs

> **Status note.** `CANDIDATE` proposal, governed by `ADR-003` (Accepted). Sprint decomposition is tentative until the owner promotes `1.8.0`.

## 1. Purpose

`1.7.0` gives the Wildboard a place to put things. `1.8.0` makes it pleasant to write there and possible to find things again.

Two influences:

- **Medium** — writing should feel like formatting a document, not typing syntax: a floating toolbar on selection, a `/` menu on an empty line, drag handles for blocks, clean typography.
- **Spatial** — labels on spaces, a sidebar layer list, and fast local search.

The constraint that must survive both: **Markdown remains the stored format**. The editor is a presentation layer over `.md`, never a new document format.

## 2. Scope

**In scope**

- Block-based editor with Markdown round-trip and a Source toggle.
- Medium-style formatting UX: selection toolbar, slash menu, block drag handle.
- Blocks: paragraph, headings, bulleted/numbered lists, quote, code, divider, table, internal link, image reference.
- Labels on spaces.
- Sidebar layer view.
- Wildboard-scoped search.

**Out of scope**

- real-time collaboration,
- comments/annotations inside the editor (`1.6.0` covers review notes separately),
- DOCX editing (remains Microsoft Word Desktop),
- media import beyond image references (`1.9.0`).

## 3. Editor model

### 3.1 Block types and Markdown mapping

| Block | Stored as |
|---|---|
| Paragraph | plain text |
| Heading 1/2/3 | `#` / `##` / `###` |
| Bulleted list | `- ` |
| Numbered list | `1. ` |
| Quote | `> ` |
| Code | fenced code block |
| Divider | `---` |
| Table | pipe table |
| Internal link | `[[wikilink]]` (existing `MD-04` resolution) or `[text](relative.md)` |
| Image | `![alt](vault-relative-path)` |
| Link | `[text](url)` |
| Bold / italic / inline code / strikethrough | `**` / `*` / `` ` `` / `~~` |

Rules:

- Round-trip must be lossless for supported constructs. Constructs the editor cannot render are shown in a preserved raw block and are never silently rewritten.
- Pasting HTML is normalized to equivalent Markdown; pasting Markdown is preserved; pasting plain text becomes paragraphs.
- Unknown syntax is preserved verbatim (forward compatibility).

### 3.2 Interaction

- **Selection toolbar** — selecting text raises a compact, keyboard-reachable toolbar (bold, italic, code, link, heading, quote, list).
- **Slash menu** — typing `/` on an empty block opens a filterable block menu (heading, list, quote, code, divider, table, image, internal link).
- **Block handle** — hovering a block shows a drag handle; dragging reorders blocks; the handle exposes a block menu (duplicate, delete, convert).
- **Keyboard** — `Enter` splits a block, `Backspace` on an empty block merges upward, `Tab`/`Shift+Tab` indents list items, undo/redo follows the existing history semantics.
- **Source toggle** — a visible, keyboard-bound action switches the same file to raw Markdown editing and back; switching never mutates content.

### 3.3 Amendment to "source-first"

The Markdown specification currently requires source-first editing. This version changes the *default editing surface*, not the storage contract:

- **Was:** the editor edits Markdown source directly.
- **Becomes:** Markdown is the canonical stored representation; the editor offers a rich block mode (default) and a raw source mode (always available), and every save round-trips through Markdown.

This is a product-scope change and must be approved as an explicit spec amendment, not applied silently. File format, sanitization (`MD-02`), and save-safety semantics are unchanged.

## 4. Labels on spaces

- A `label` object renders as a text heading on the canvas.
- Labels group spatially (the user places them); they do not create a hierarchy or query.
- Labels are metadata-only (`vault_relative_path` is `NULL`).
- A label never renames files or folders.

## 5. Sidebar layer view

A structured list of the current wildboard's objects:

- grouped by kind or by stack,
- virtualized for large boards,
- selecting a row focuses and selects the object on the canvas,
- reordering rows reorders z-order only, never files.

## 6. Wildboard search

- A wildboard-scoped index covers `text` and `sheet` content.
- Results are labelled by object kind and are visually distinct from document results.
- Query grammar extends the existing structured parser rather than introducing a second one.
- Indexing is incremental and runs through the existing background-job model.
- If a separate index is chosen over reusing the document pipeline, the index must be rebuildable from the vault.

## 9. Acceptance criteria

- [ ] A document written in the block editor stores valid plain Markdown.
- [ ] Source toggle shows the exact bytes that will be written to disk.
- [ ] Round-trip of every supported construct is lossless.
- [ ] Unknown Markdown syntax survives a rich-mode edit unchanged.
- [ ] Slash menu, selection toolbar, and block handle are keyboard reachable.
- [ ] Labels are metadata-only and never rename or move files.
- [ ] Layer view rows focus the matching canvas object.
- [ ] Wildboard search returns staged results within the existing interaction budget.
- [ ] No document-only subsystem becomes reachable from a wildboard.

## 10. Non-goals

- WYSIWYG-only storage (HTML/blocks in the database),
- Word-compatible DOCX authoring,
- real-time co-editing,
- font/theme selection beyond the design system,
- export to proprietary formats as the primary path.

## 11. Risks & open questions

1. **Round-trip fidelity.** rich → Markdown → rich can normalise formatting; the preserved-raw-block rule must be enforced by tests.
2. **Accessibility.** A canvas-adjacent rich editor must keep keyboard and screen-reader paths; a non-canvas alternative is required by the shared contracts.
3. **Two search paths.** Document FTS and wildboard search must not diverge into inconsistent ranking semantics.
4. **Open question:** whether the block editor also replaces `MD-01` for `documents` workspaces or stays wildboard-only in this version.
