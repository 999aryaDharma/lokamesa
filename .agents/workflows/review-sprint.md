# Review Sprint

## Description

Independent review of a completed implementation sprint.

## Steps

1. Confirm reviewer is not the sprint implementation owner.
2. Read `AGENTS.md`, sprint spec, Required Reading, security/file-safety gates, and Definition of Done.
3. Inspect the actual code, diff, tests, and handoff.
4. Re-run high-value verification where practical.
5. Check:
   - acceptance criteria,
   - architecture boundaries,
   - file safety/security,
   - failure paths,
   - performance constraints,
   - scope creep,
   - missing/skipped tests.
6. Report findings as CRITICAL/HIGH/MEDIUM/LOW with exact evidence.
7. End with `APPROVE`, `CHANGES REQUIRED`, or `BLOCK`.
8. Do not modify code unless explicitly assigned a subsequent fix role.
