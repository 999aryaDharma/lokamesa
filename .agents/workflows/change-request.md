# Change Request

## Description

Evaluate a new/changed product requirement before coding.

## Steps

1. Do not modify implementation.
2. State requested behavior clearly.
3. Compare against master/subsystem specs.
4. Identify architecture, data-model, security, file-safety, UI, migration, and sprint impacts.
5. Identify completed sprints that would need reopening.
6. Produce a Change Request using `docs/templates/CHANGE-REQUEST-TEMPLATE.md`.
7. If architecture/security boundary changes, also propose an ADR.
8. Wait for product-owner approval before implementation.
